Architecture

High-level block diagram · Spill

The Expo client runs on user devices under user-controlled conditions. Auth and data access are enforced by Firebase Auth, Firestore rules, and Cloud Functions (Admin SDK). Third-party APIs are reached from server-side code or via keys that must not ship in the client.

Trust boundary 1 · User device (client)

Expo / React Native app

UI (tabs, screens), local state, Expo Router; no trusted secrets.

→

Firebase JS SDK (client)

Auth session, Firestore & Storage calls; subject to security rules.

↓ HTTPS / TLS to Google Cloud (session tokens, signed requests)
Trust boundary 2 · Firebase / Google Cloud (backend of record)

Firebase Authentication

Email/password, session tokens, email verification; custom claims for roles where used.

→

Cloud Firestore + rules

Primary data store; rules restrict reads/writes by uid and role.

↓

Cloud Storage

Media uploads; access controlled via rules and metadata.

→

Cloud Functions (Node)

Trusted writes, callables, triggers; Admin SDK bypasses client rules only inside controlled code.

↓ Server-side and secure client egress (API keys, tokens, streaming endpoints)
Trust boundary 3 · External services

Perspective API

Toxicity scoring on new posts (via Cloud Functions).

→

Transactional email

Therapist invites, login OTP, etc. (SMTP / provider from Functions).

→

Expo push notifications

Device tokens registered; pushes orchestrated from the backend.

↓

LiveKit

Real-time audio for live podcasts (@livekit/react-native, LiveKit Cloud); participants join using short-lived tokens issued from trusted code (Functions / server).

→

OpenAI API

Model calls for AI-assisted features (e.g. admin resource tooling); API keys belong in controlled config: prefer server-side or restricted keys rather than embedding full secrets in the client bundle.

→

AssemblyAI

Streaming speech-to-text over WebSocket (wss://streaming.assemblyai.com) inside the live podcast WebView transcript path.

Legend (cross-reference in testing chapter)

Symbol / region Meaning
Arrows (→, ↓) Abbreviated flow: left-to-right inside a trust boundary; downward links between boundaries. Not every production integration is shown.
Dashed border Trust boundary: policy and threat modelling are stated at this perimeter.
Solid blocks Major components; arrows in prose indicate data or control flow between neighbours.
Functions + Admin SDK Privileged operations (moderation, email, merges) must not rely on client-side checks alone.
LiveKit / AssemblyAI / OpenAI Third-party realtime and AI endpoints sit outside Firebase; route keys and tokens through policies that minimise exposure (e.g. server-minted LiveKit tokens, avoid long-lived OpenAI keys in the app binary).
